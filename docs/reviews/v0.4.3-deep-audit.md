# v0.4.3 Deep Audit — Math, Architecture, Efficiency

**Branch:** `review/v0.4.3-deep-audit`
**Base:** v0.4.0 (`e88a336`) — last library-first reset
**Head:** v0.4.3 (`3fe10ec`)
**Reviewers:** three parallel reviewer agents, each scoped to one dimension.

This is a full-state review of the released v0.4.3 surface, not a diff-only review. Findings are grouped by dimension; severities are reviewer-assigned.

## TL;DR

| Dimension | Verdict | Top concern |
|---|---|---|
| Math / statistics | Mostly sound with fixes | "Transfer entropy" surface computes residual-MI, not Schreiber TE; AMI/pAMI public path is KSG-I single-k while docs say KSG-II + median-over-k |
| Architecture / code quality | Solid with fixes | No physical `domain/` directory — hexagonal layering enforced by a hand-curated allowlist with a documented `# TODO` escape |
| Efficiency | Significant perf debt | "Batched" kNN MI kernel is a Python loop calling sklearn per pair; tree rebuilt 12 000+ times per surrogate band on realistic inputs |

The math is stronger than the marketing reads; the architecture is stronger than the interior reads; the perf debt is exactly as suspected — concentrated in the hot loops, with the *right* vectorized pattern already present in one reference module (`ami_information_geometry_service._ksg2_median_profile_value`) and not propagated to the rest.

## 1 — Math & Statistics

### Strengths

- **KSG-II is correctly implemented in the geometry path** (`services/ami_information_geometry_service.py:112-164`): Chebyshev metric, marginal ε_x/ε_y from joint-neighbour radii, `searchsorted` with `-1` for self-exclusion, formula matches Kraskov 2004 Eq. 9.
- **Median-over-k** with `k ∈ {3,5,8}` and a one-shot global jitter (applied once per series, not per k) is a defensible bias/variance compromise.
- **Phase surrogates are Hermitian-correct** (`diagnostics/surrogates.py:33-63`): DC bin and (even-N) Nyquist bin keep phase 0; interior phases uniform on `[0, 2π)`. Parity test verifies `|rfft(surrogate)| ≈ |rfft(original)|` to ~1e-10.
- **GCMI** (`diagnostics/gcmi.py`) — textbook Ince 2017 with proper `_RHO_CLIP` guard.
- **DFA** (`services/memory_structure_service.py:45-68`) — profile via cumsum-of-centred, polynomial-1 detrending per segment, log-log polyfit, R² guard before reporting α.
- **Ordinal permutation entropy** uses the **Fubini number** `Σ_k k!·S(m,k)` for tie cardinality (`services/ordinal_complexity_service.py:45-65`) — rarely seen, correct.
- **Lag-aware ModMRMR forecast-safety** (`services/lag_aware_mod_mrmr_domain.py:154-180`) enforces `lag ≥ horizon + margin` before the scoring pool is constructed — leakage gate is in the right place.
- **Determinism**: `SeedSequence.spawn` for surrogates; serial-vs-parallel bit-identity is tested.

### Critical

- **C1 — `compute_transfer_entropy` is not Schreiber TE.** `diagnostics/transfer_entropy.py:87-162` + `diagnostics/cmi.py:220-297` define TE as `I(future_residual; past_residual)` after regressing both on the target-history conditioning matrix. With `backend="linear_residual"` (default) this removes only the *linear* projection — Granger-style residual MI, not CMI `I(Y_t; X_{t-L} | Y_{t-1..t-L+1})`. RF/ET backends fix linearity but introduce un-calibrated bias from RF residuals. Docstring writes the Schreiber formula; users will mis-cite. **Fix:** rename to `compute_te_residual` / `compute_predictive_information_gain`, or implement a Frenzel-Pompe KSG-CMI backend (~30 lines on top of `_ksg2_single_k`).
- **C2 — No multiple-testing correction across lags.** `services/significance_service.py:136-137` and the geometry-engine `corrected > 3·τ_90` rule (`ami_information_geometry_service.py:404, 410`) compute per-lag thresholds with no family-wise control over `max_horizon`-many tests. Over-acceptance propagates into `information_mass`, `informative_horizons`, `signal_to_noise`, and routing confidence labels. **Fix:** Romano-Wolf step-down using the surrogate matrix already in memory, or Benjamini-Hochberg over lags. One pass over data.
- **C3 — Public AMI / pAMI helpers are KSG-I single-k, not KSG-II.** `metrics/metrics.py:43, 92, 150, 210` delegate to `sklearn.feature_selection.mutual_info_regression` (sklearn ships Kozachenko-Leonenko single-fixed-k). The KSG-II + median-over-k path lives *only* inside `compute_ami_information_geometry`. Every other public AMI/pAMI surface — including the surrogate-band scoring, `_compute_raw_curve_prescaled`, `_compute_partial_curve_prescaled`, the README curves and Medium article figures — ships KSG-I. Paper-vs-code drift. **Fix:** route every curve through the geometry kernel, or label `compute_ami` as "KSG-I via sklearn" everywhere.

### Important

- **I1 — "Calibrated confidence" is not calibrated.** `services/routing_confidence_calibration_service.py:21-79` is a hand-picked decision table mapping penalty integers + two scalar thresholds to confidence labels. No reliability diagram, no held-out set. Rename or actually calibrate against the 10-archetype synthetic suite that already exists.
- **I2 — 10 synthetic archetypes / geometry classifier are heuristic.** Peak-prominence `0.10`, SNR floor `0.05`, shift-correlation cutoff `0.60` are reasonable for demos but should not be called "deterministic" as a stand-in for "principled".
- **I3 — pAMI via linear residualisation ≠ partial MI** except under joint Gaussianity. Function name is honest (`compute_pami_linear_residual`) but the public docstring should say so explicitly.
- **I4 — Lyapunov.** Rosenstein fit window not restricted to the linear-divergence region (`metrics/scorers.py:723-728` polyfits the whole curve); `m=3, τ=1` hard-coded defaults aren't derived from first-AMI-minimum / FNN. `_CHAOTIC_THRESHOLD = 0.1` is arbitrary. Class docstring honestly tags as experimental.
- **I5 — Welch PSD `nperseg=arr.size`.** `services/spectral_forecastability_service.py:135-139` degenerates Welch into a single periodogram (no overlap, no averaging, no variance reduction). Use `nperseg = N // 8`, default 50% overlap.
- **I6 — KSG-II self-exclusion via `1:k+1` index slice** (`ami_information_geometry_service.py:147-158`) assumes sklearn's neighbour ordering returns the query as index 0. Not asserted — silent breakage risk if backend swaps.
- **I7 — Tie handling.** `1e-7·std` global jitter is fine for unique-valued continuous series; fails on integer counts / sensor saturation / calendar features. Add cardinality detection that routes to GCMI / rank-MI fallback.
- **I8 — CMI sample-size rule is independent of conditioning dimension.** `diagnostics/cmi.py:163-174` enforces `2*min_pairs` regardless of `h`; KSG-style CMI requires `N ≳ k^(d+2)`. Residualisation backends quietly degrade at large h.
- **I9 — `signal_to_noise` is a coverage statistic, not an SNR** (`ami_information_geometry_service.py:413-420`). Rename to `informative_mass_fraction`.
- **I10 — `nonlinear_share` is a Gaussian-information differential** with the bound `[0, 1]` coming from `max(..., 0) / Σ`, not from information theory. Bounded but not interpretable as "fraction of nonlinear MI".

### Minor

- KSG-II docstring should specify "KSG-II / max-norm projection (Kraskov 2004, Eq. 9)".
- `routing_policy_service` `policy_version="v0.3.1"` while package is v0.4.3 — note that it's intentionally frozen.
- `n_surrogates ≥ 99` floor uses `np.percentile` directly; consider `(B+1)`-corrected ranks (Davison-Hinkley) and recommend `B ≥ 999` for the geometry threshold.
- DFA `np.geomspace(4, N//4)` can yield far fewer than `n_scales=12` unique integer values for short N; threshold `len(valid_scales) < 5` is not strict enough.
- `_classify_periodicity_hint` `0.6·predictability + 0.4·concentration` is hand-weighted; document or cite.
- `tests/test_cmi.py` checks shape/finiteness/raises but has **no numerical assertion** against a known-MI baseline. Adding a Gaussian round-trip (`ρ → -½log(1-ρ²)` within 5%) would catch C3 and I3 immediately.

### Math/stats verdict

**Mostly sound with fixes.** Core estimators are textbook-correct; the issues that will mislead users are concentrated in three places (C1, C2, C3) plus the "calibrated" naming. Fix those four and the math story matches the implementation.

## 2 — Architecture & Code Quality

### Strengths

- **AST boundary tests are real**, not theatre. `tests/test_architecture_boundaries.py` parses files via `ast`, walks imports, enforces 6 rules (`_DOMAIN_FORBIDDEN`: pydantic_ai, fastapi, mcp, httpx, click, typer, matplotlib; `_PORTS_FORBIDDEN` adds sklearn, scipy, pandas, statsmodels). Rule 5 forbids reverse coupling (adapter utilities → primary transport adapters) — the right kind of leak to catch.
- **Frozen Pydantic v2 is pervasive** — closer to 80+ frozen models than the README's claimed "12+". `utils/config.py` (24+), `utils/types.py` (every model), `triage/models.py`, `triage/lag_aware_mod_mrmr.py` (8 including the new `LagAwareModMRMRResult`).
- **Validators enforce domain invariants**, not just bounds. `ExogenousBenchmarkConfig._validate_slice_case_ids` (`utils/config.py:117-137`) checks exact set membership against the paper's fixed slice. `HTTPRequest` enforces `n_surrogates >= 99` at the API boundary, mirroring the internal `ReadinessReport` gate.
- **Readiness gate uses typed Result variants, not exceptions.** `triage/readiness.py` returns `ReadinessReport(status=blocked, ...)` on failure; `use_cases/run_triage.py` short-circuits to `TriageResult(blocked=True)` — never raises across the use-case boundary. Right pattern for triage.
- **Live agent fallbacks log+degrade.** `adapters/llm/fingerprint_agent.py:433-437` and `routing_validation_agent.py:266-270` catch broad `Exception` and return deterministic `_strict_explanation(...)` — bare `Exception` is justified at the LLM provider boundary.
- **Lazy loading is correctly implemented** with PEP 562 `__getattr__` (`src/forecastability/__init__.py:326-342`), caches via `globals()[name] = value`, supports module-as-attribute.
- **`py.typed` present** (correct 0-byte format).
- **Conftest discipline:** session-scoped deterministic AR(1) fixtures, autouse loky teardown.

### Critical

- **C1 — There is no `src/forecastability/domain/` directory.** The "domain layer" is a hand-curated allowlist of 18 paths scattered across `utils/`, `metrics/`, `diagnostics/`, `triage/`, `pipeline/`, `reporting/` (`tests/test_architecture_boundaries.py:40-67`). The boundary test is doing real work, but it's enforcing a *virtual* layer. New contributors looking for `domain/` find nothing; new models that should be domain require manually editing the allowlist. **Fix:** physically create `domain/` and migrate, or drop "hexagonal" framing from public docs and describe what actually exists (port-and-adapter at the boundary, "no infra deps from compute code" rule).
- **C2 — `triage/comparison_report.py` is an architectural escape hatch.** `tests/test_architecture_boundaries.py:78` literally reads `# C15: TODO — comparison_report.py imports matplotlib; excluded until fixed`. Documented violation passing the suite by omission. **Fix:** split into a domain-pure model in `triage/` and a renderer in `reporting/`. Re-include in `DOMAIN_MODULE_PATHS`.

### Important

- **I1 — `__init__.py` is 490 lines re-exporting ~120 symbols.** Lazy loading hides surface but doesn't shrink it. `_LAZY_EXPORT_MAP` and `_NOTEBOOK_COMPAT_EXPORTS` register dozens including entire modules (`"exog_benchmark": (..., "")`). Pyright/mypy users see every name on the package. Split into `forecastability.api` (~20 canonical names) + a deprecation facade for notebook compat.
- **I2 — `adapters/pydantic_ai_agent.py` issues `DeprecationWarning` at import time, not at use.** Because `_NOTEBOOK_COMPAT_EXPORTS` re-registers `create_triage_agent` under the old path, anyone touching the public API triggers the warning transitively. Move into `__getattr__` or remove the shim.
- **I3 — `adapters/agents/` (2 000 LoC) vs `adapters/llm/` (1 500 LoC) split is unmotivated.** Both contain "fingerprint_agent", "covariant_agent", "triage_agent", "routing_validation_agent" components — one as payload DTOs/serialisers, the other as live PydanticAI wiring. Merge under `adapters/agents/{payloads, runtime}/`.
- **I4 — `use_cases/requests.py` and `use_cases/responses.py` are dead DTOs.** Tagged "internal contracts for future agent integration" but they embed raw `np.ndarray` with `arbitrary_types_allowed=True` (not serialisable, defeats the point of a request DTO), aren't frozen, have no callers. The "future agent integration" landed in `adapters/agents/*_payload_models.py` instead. Delete or wire up.
- **I5 — `extensions.py` and `exog_benchmark.py` are orphan use-cases at the top level.** Both define orchestrator functions (`compute_k_sensitivity`, `bootstrap_descriptor_uncertainty`, `run_benchmark_exog_panel`, `build_case_summary`) — they *are* use cases by behaviour but aren't under `use_cases/`. `adapters/causal_rivers.py:13` imports from `extensions` (adapter → top-level orphan). Move to `use_cases/`.
- **I6 — Type narrowness leaks at agent boundaries.** Agent tool returns are uniformly `dict[str, Any]` (`adapters/llm/triage_agent.py:164, 172, 182, 278, 292, 313` + fingerprint/covariant agents). The LLM contract is the worst place to drop frozen-Pydantic discipline — mistakes only surface as production hallucinations. Return frozen Pydantic models from tools; PydanticAI supports it.
- **I7 — `use_cases/requests.py` and `responses.py` use `arbitrary_types_allowed=True`** and aren't frozen. If kept, harden them; if not, delete (see I4).
- **I8 — Reporting entry-point sprawl.** `reporting/fingerprint_showcase.py` (532) + `reporting/extended_fingerprint_showcase.py` (1 082) + `triage/comparison_report.py` — three "showcase/report" subsystems with overlapping responsibilities. Consolidate behind one facade (`reporting.build_showcase(kind=...)`).

### Minor

- 8 places catch `OSError`/`KeyError`/`ValidationError` and re-wrap as `ValueError` (e.g. `utils/io_models.py:27-34`, `triage/result_bundle.py:141-146`), losing the original error class.
- Half the model docstrings restate signatures (violates the stated "no comments unless WHY is non-obvious" rule).
- 30+ tests use `assert ... is not None` as the only assertion (e.g. `test_triage_run.py`, `test_pydantic_ai_agent.py`). `test_lag_aware_mod_mrmr.py` is the standard the rest should reach — it asserts determinism numerically.
- Only `slow` is registered as a pytest marker; add `network`, `integration`, `agent`. `tests/test_dashboard.py` uses `importorskip` instead of marker gating.
- `[tool.mypy]` / `[tool.pyright]` absent from `pyproject.toml` (only Astral `ty` configured). `py.typed` ships but the supported checker baseline isn't documented.

### Code-quality verdict

**Solid with fixes.** Boundary discipline at the seams is genuine; the gap is in the interior. C1, C2, I4, I5 are roughly one week of focused work that would close the "hexagonal" claim. Otherwise the public surface (490-line `__init__.py`, two parallel agent-folder hierarchies, dead DTO modules) is debt that compounds.

## 3 — Efficiency (user-flagged weakest dimension — confirmed)

### Strengths

- **`ami_information_geometry_service._ksg2_median_profile_value`** (`L112-164`) is the *correct* vectorized KSG-II profile: one `NearestNeighbors(metric="chebyshev")` build, one `kneighbors` call for `k_max+1`, then `_ksg2_single_k` slices `indices[:, 1:k+1]` and counts marginals via `np.searchsorted` on pre-sorted arrays. This is the reference pattern.
- **One-shot jitter** applied once per series, not per k or per surrogate.
- **`_lag_design.build_intermediate_design`** uses single `column_stack`; `residualize_with_intercept` shares an augmented design across past/future.
- **Top-level `__init__.py` is properly lazy** — matplotlib, statsmodels, pydantic-ai, reporting behind `__getattr__`. Sub-second `import forecastability` warm.
- **Welch PSD via `scipy.signal.welch`** is fully vectorized.

### Critical

- **C1 — `PurePythonBatchedKnnMiKernel` is a Python loop calling sklearn per pair.** `kernels/batched_knn_mi.py:42-55` literally iterates `for past, future in pairs:` and calls `mutual_info_regression`. For one surrogate band on `max_lag=40, n_surr=99, k_list=(3,5,8)`: same KD-tree rebuilt 40×99×3 ≈ **12 000 times per series**. Each rebuild is O(n log n) and sklearn uses *euclidean*, not Chebyshev — KSG-II contract is silently broken too. **Estimated: 20-50× speedup.** Fix is exactly what the docstring already describes.
- **C2 — Every `compute_*_curve` rebuilds the kNN tree at every lag.** `services/raw_curve_service.py:88-133` and `partial_curve_service.py:146-197` — per-lag loop calling `_mi_scorer`, which calls `mutual_info_regression` (fresh tree per call). For one surrogate band: `max_lag=40 × n_surr=99 × ≥2 metrics ≈ 7 920 kNN builds per series`. The marginal Chebyshev counts could use `searchsorted` on pre-sorted arrays — pattern already present in `_ksg2_single_k`. **Estimated: 10-30× speedup on `compute_significance_bands_generic`.**
- **C3 — ModMRMR O(p²) redundancy matrix with quadratic kNN work, computed *twice*.** `services/lag_aware_mod_mrmr_selector.py:212-238`: `for i, st_a: for j, st_b:` with only `if i == j: continue` — both `(i,j)` and `(j,i)` computed though MI is symmetric. For `p = 20 covariates × 10 lags = 200`: **39 800 MI calls**, fresh kNN tree each. **Estimated: ≥2× from de-duplication alone, 10-40× total for `p > 50`.** Also: `mrmr.tie_break_key` re-sorts the full remaining list every greedy iteration (`O(K·p·log p)` instead of `O(K·p)` argmax).
- **C4 — `_distance_scorer` materializes two N×N float64 matrices per call.** `metrics/scorers.py:358-399`. For N=10 000 that's ≈ 800 MB per matrix, ≈ 1.6 GB before centring doubles it. Scorer is registered in `default_registry()` without an "off-by-default for production" flag. The 20 000 N cap is necessary but insufficient.

### Important

- **I1 — Phase-surrogate generation: per-surrogate Python loop, 99 separate irffts.** `diagnostics/surrogates.py:33-63` does the right thing pre-computing `rfft` once, but the inner loop generates one random phase vector per surrogate and one `irfft` per surrogate. Vectorize: generate `(n_surr, n_freq)` phases in one RNG call, batched `np.fft.irfft(spectrum[None, :] * phase, axis=1)`. **Estimated: 5-10×** (FFT releases GIL, parallelizes internally).
- **I2 — Surrogate-band parallelism mismatch.** `surrogates.py:124` uses `ProcessPoolExecutor` (correct for AMI/pAMI path), but `significance_service.py:132` uses `ThreadPoolExecutor` on Python-bound work — saturates 2-3 cores at best. Make scorers picklable, switch to processes / loky to match. **Estimated: 3-5×** on multi-core surrogate work.
- **I3 — `_eval_surrogate` re-scales every surrogate via `StandardScaler().fit_transform`.** Hundreds of microseconds of pure Python overhead × 99 × 2 metrics × n_series. Replace with `(x - x.mean()) / x.std()`. **5-20% off surrogate-band wall-clock.**
- **I4 — `_compute_partial_curve_prescaled` rebuilds full intermediate design *and* re-residualises both past+future per lag.** Total cost is `O(max_lag³ · n)`. Streaming QR / incremental Cholesky reduces to `O(max_lag² · n)`. `scipy.linalg.qr_insert` is the primitive. **Estimated: 3-10× for max_lag ≥ 30.**
- **I5 — `_estimate_joint_mi` uses `query_ball_point` with list-comp counting.** `services/predictive_info_learning_curve_service.py:129-134` — `[len(nb)-1 for nb in query_ball_point(...)]` is hundreds of thousands of Python `len()` calls. scipy supports `return_length=True` returning a numpy array. **Estimated: 2-4×**, 4 lines.
- **I6 — `_select_valid_nn` is a double Python loop.** `metrics/scorers.py:606-629`. Up to 23 000 Python comparisons for typical n. Vectorize with `np.abs(indices_k - np.arange(n_e)[:, None]) > theiler_window` + `argmax`. **50-100× on the filter, ~10× on full Rosenstein LLE.** LLE is always called unconditionally in `run_triage` (`run_triage.py:449`).
- **I7 — `_dfa_fluctuation` is a Python loop over segments.** `services/memory_structure_service.py:46-68`. Reshape into `(n_segments, scale)`, vectorize the OLS detrending. **10-30×.**
- **I8 — PCMCI-AMI Phase 0 dispatches one joblib task per (target × source × lag) triplet.** `adapters/pcmci_ami_adapter.py:137-157`. 250 tasks for 5×5×10 triplets, each pickling overhead competes with the few-ms MI call. Chunk by `target_idx`. **2-5× on Phase 0.**
- **I9 — TE with RF/ET backend fits 160 fresh `RandomForestRegressor(n_estimators=200)` per curve.** `diagnostics/transfer_entropy.py:188-216` + `cmi.py:270-289`. Single curve on n=2000 takes 10-60 s. Reduce default `n_estimators` to ~50 for screening, document as research-grade not production.

### Minor

- `_get_ordinal_patterns` uses dict-of-tuples lookup per window (~5 µs each); encode rank-tuple to base-m int and index into a NumPy array (~5× speedup).
- `_compute_log_divergence` per-step `for j in range(evolution_steps)`: vectorizable with `(n_pairs, evo, m)` 3-D allocation (~60 MB for typical sizes, fine). 5-10× for LLE.
- `_dcov_centred` materializes 4×n² floats per call (already in C4).
- Use `scipy.fft` with `workers=-1` over `np.fft` once I1 is batched.
- Repeated `_scale_series` in `*_at_horizon` helpers (`metrics/metrics.py:145, 196`); 30-100 µs / call, replace with closed-form.

### Caching

**There is no AMI / pAMI / spectral memoization anywhere** — no `functools.lru_cache`, no `joblib.Memory`. Within one `run_triage` call the same series is processed by `_run_compute` (AMI/pAMI curves), `build_forecastability_profile`, `build_complexity_band` (recomputes spectral entropy + PE from scratch — `services/complexity_band_service.py:129-130`), `build_theoretical_limit_diagnostics`, `build_largest_lyapunov_exponent`, and optionally `run_extended_forecastability_analysis` (recomputes full AMI geometry). **Estimated: 1.3-2× on `run_triage` from caching `_scale_series`, `compute_normalised_psd`, and the raw KSG-II AMI profile within a single call.**

### PBE tests

**There are no PBE-F* tests that enforce time or memory budgets.** `test_performance_phase1_scripts.py` is a smoke test checking YAML config shape. No `pytest-benchmark`, no `tracemalloc` guard, no `assert elapsed < X`. The only `time.perf_counter` use is observability in `_StageTimer`. PBE-F08/F23 tags in code are *correctness/memory-guard* contracts, not perf budgets. **No regression detection exists for any of the hotspots above.**

### GIL & multiprocessing

Inconsistent mix across three sites:
- `surrogates.py:124` — `ProcessPoolExecutor` (correct).
- `significance_service.py:132` — `ThreadPoolExecutor` (GIL-bound).
- `run_batch_forecastability_workbench.py:386` — `joblib.Parallel(loky)` (correct).
- `pcmci_ami_adapter.py:144` — `joblib loky` (correct but triplet-granularity).
Nested oversubscription almost certain when more than one knob is turned up; `run_batch_*` doc at line 363 warns but leaves to caller.

### Top 3 deeper investments

- **D1 — Curve-level kNN MI kernel sharing tree across lags and k-values.** Rewrite `PurePythonBatchedKnnMiKernel` to accept `(series, predictor, lag_range, k_list)` and return `(n_lags, n_k)`. One Chebyshev `cKDTree` per joint slice, `searchsorted` on pre-sorted marginals. The port `ports/kernels.py:120-148 Ksg2ProfileKernel` already declares this contract. **10-30×** on `compute_significance_bands_*`.
- **D2 — Incremental QR for per-lag OLS residualisation.** Build full lag matrix once for `max_lag`; maintain thin-QR; add one column per lag-step; back-substitute. Reduces partial-curve from `O(max_lag³·n)` to `O(max_lag²·n)`. **3-10× for max_lag ≥ 30.**
- **D3 — Request-scoped memoization in `run_triage`.** Cache `_scale_series`, `compute_normalised_psd`, raw KSG-II AMI profile keyed by `id(request.series)` + parameters. **1.3-2× on `run_triage`, 1.5-2× on `run_batch_forecastability_workbench`.**

### Efficiency verdict

**Significant perf debt.** The scaffolding for a fast kernel exists (the `KernelProvider` ports, the reference `_ksg2_median_profile_value`) but production paths still use the pre-port "scalar Python loop calling sklearn per lag/surrogate/pair" pattern. `PurePythonBatchedKnnMiKernel` is an explicit parity oracle, not optimised. No perf regression test exists. The lazy import layout is genuinely good; the math hot loops are not. Top-5 quick wins land in an afternoon; the three deeper investments change the asymptotic ceiling.

## Cross-cutting takeaway

The same root cause shows up in all three dimensions: a **declared contract** (hexagonal layering / KSG-II + median-over-k / fast kernel via ports) that is **honored in one canonical place** and **not propagated** to the rest.

- Architecture: `tests/test_architecture_boundaries.py` is rigorous, but `domain/` is virtual and `comparison_report.py` is excluded with a `# TODO`.
- Math: `compute_ami_information_geometry` does KSG-II correctly, but every other AMI/pAMI public path falls through to sklearn's KSG-I.
- Efficiency: `_ksg2_median_profile_value` is the reference vectorized hot loop; `PurePythonBatchedKnnMiKernel` and the curve services don't follow it.

The right next step is not a refactor scattered across the codebase — it's making the canonical implementations *the only implementations* of their respective contracts. One unified KSG-II kernel that every curve service routes through fixes C3 (math), removes ~70% of the perf hotspots (efficiency), and naturally suggests the domain/use_cases boundary that's currently virtual (architecture).
