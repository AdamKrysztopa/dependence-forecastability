## Detailed findings

### CR-01 — Significance test compares corrected observed against an un-corrected null *(High)*
`services/ami_information_geometry_service.py:459` computes `corrected = np.where(valid_mask, np.maximum(raw - bias, 0.0), np.nan)` with `bias = nanmean(shuffle_matrix)`. Line 484 then calls `svc.correct(shuffle_matrix, obs_for_correction)` passing the **raw** `shuffle_matrix` as the null while `obs_for_correction` is the **bias-subtracted** `corrected`. `_compute_raw_p_values` counts `shuffle ≥ corrected`. Because `corrected ≤ raw` while the surrogate null still carries the full bias mass (mean ≈ `bias`), a weak-but-real lag whose corrected value sits inside the surrogate bias mass is ranked against surrogates centred *above* it.

- Direction is **strictly toward false negatives** (`corrected ≤ raw` ⇒ comparison only ever more conservative).
- **New in v0.5.0**: `git show main:` of this service has only the single `corrected > horizon_multiplier·tau` percentile path; the `correction != "none"` branch and the `SignificanceCorrectionService` dependency are new.
- The default is `correction="romano_wolf"` (line 413) → **this is the default path**.
- Reproduced: a real lag at `corrected=0.06` with raw-surrogate mean `0.10` → p≈0.91 (not significant) via the code path vs p≈0.03 under a like-for-like comparison.
- **Fix direction:** pass a bias-subtracted null (`shuffle_matrix - bias`) or pass `raw` as the observed so observed and null share a baseline. → **statistician → coder**.

### CR-02 — Monte-Carlo p-value denominator ignores NaN surrogates *(High)*
`services/significance_correction_service.py:195`: `exceed` is tallied with `np.nansum` over valid surrogates, but the denominator is the full `n_surrogates + 1`. For a lag with 50/100 valid surrogates the count is over 50 yet divided by 101 → **deflated, anti-conservative** p. Degenerate case: an **all-NaN surrogate column with a finite observed** yields `raw_p = (0+1)/(n+1)` → declared significant with **zero valid surrogate evidence**. Corrupts `corrected_mask` for `none`/`bh`/`by` and the `romano_wolf` subset-max null. **Fix:** divide by per-lag valid-surrogate count (`+1`), or propagate NaN p for all-NaN columns. → **statistician → coder**.

### CR-03 — `compute_ami` mixes nats and bits *(High)*
`metrics/metrics.py:95-103`: when `cardinality_ratio < _GCMI_CARDINALITY_THRESHOLD` the curve is built from `compute_gcmi_at_lag`, which returns **bits** (`diagnostics/gcmi.py:67`, `-0.5*np.log2(...)`). The `ksg2` (and `ksg1_sklearn`) paths at `:105+` return **nats** (digamma estimator, no base conversion). The same public function therefore emits curves on scales differing by `1/ln 2 ≈ 1.4427` purely as a function of input cardinality. Any consumer comparing AMI to a nats threshold, or comparing the two regimes, mis-scales by ~44%.

Related routing inconsistency: `KSG2CurveKernel.estimate_curve` (`kernels/ksg2_curve_kernel.py:112`) uses a **different** low-cardinality threshold (`0.5`) and only **warns + jitters** (no GCMI fallback, stays in nats). Two low-cardinality entry points, two thresholds, two behaviours. **Fix:** convert GCMI bits→nats (`* ln 2`) before returning from `compute_ami`, and unify the threshold/behaviour across both entry points. → **statistician → coder**.

### CR-04 — Transfer entropy can be negative *(High)*
`diagnostics/cmi_ksg.py:97` returns `cmi = psi(k) + mean(psi(n_z) - psi(n_xz) - psi(n_yz))` unclamped; `compute_transfer_entropy_ksg` passes it straight to `value` (`:229`). The result field `transfer_entropy_ksg.py:46` has no `ge=0`. The project rule (`.github/instructions/statistician.instructions.md:22`) says TE must be non-negative. Reproduced: independent `X,Y` at `lag=1, history_depth=1, k=3, N=3000` → `status="computed"`, `value` down to `−0.0039` (5/400 seeds). **Fix:** clamp `max(0.0, value)` for the reported estimate (keep raw for diagnostics if needed), consistent with GCMI clipping. → **statistician → coder**.

### CR-05 — `compute_significance_bands` builds null and observed with different estimators *(High)*
The surrogate null is computed honouring the caller's `estimator`, but the **observed** curve is recomputed via `compute_ami`/`compute_pami_linear_residual` **without** threading `estimator`, so the observed is always the default `ksg2`. With `estimator="ksg1_sklearn"` the observed (ksg2 scale/values) is compared against a ksg1 null → wrong `corrected_mask` and wrong `+inf` upper-band masking. **Fix:** pass `estimator` into the observed-curve computation. → **statistician → coder**.

### CR-06 — `_TriageCache` is dead / doubles the AMI cost *(High, perf)*
`use_cases/run_triage.py:174` warms `cache.ami_curve(...)` (full KSG-II kNN graph), but `ForecastabilityAnalyzer` is never handed the cache and `analyzer.analyze` recomputes the curve via the module-level `compute_ami` on its own `validate_time_series` array (different `id()`, so even the `id(arr)` key could never hit). `scale_series` and `normalised_psd` wrappers have **zero call sites**; the Lyapunov consumer the docstring cites calls `compute_ami` with different params (`min_pairs=10, random_state=0`) so its key can never match; `normalised_psd` omits `noverlap` from its key. Net: the RVH-F06 cache delivers **none** of its claimed savings and **doubles** the AMI computation. The 16 cache tests pass because they assert a fresh `_TriageCache` per call, never that a recompute was avoided. **Fix:** thread the cache into the analyzer (single compute feeding all consumers) or remove the warm-up + dead wrappers. → **performance_engineer → coder**.

### CR-07 — FP marginal-count clamp injects positive bias *(Medium)*
`diagnostics/cmi_ksg.py:92-94` clamp `n_xz, n_yz, n_z` each to `≥1` before `psi()`. This breaks the Frenzel–Pompe digamma-difference matching and biases CMI upward near independence (reproduced: mean `+0.0156…+0.0267` on truly-independent data where the target is 0). **Fix:** handle the `count==0` case via the FP convention rather than an independent floor on each marginal. → **statistician**.

### CR-08 — LLE divergence-fit window collapses for short series *(Medium, regression)*
`services/lyapunov_service.py:195` `full_steps = max(1, n//20)`; `:201/:203` `linear_window = max(1, min(full_steps//3, orbital_period))`. For `n ∈ {45,55,59}`, `n//20=2`, `full_steps//3=0` → window 1 → `_estimate_lle_rosenstein` needs `≥2` points → returns **NaN** where the old `max(1, n//20)` gave a usable estimate. For larger n the window is ~3× shorter than `main` (n=300: 15→5) → the `polyfit` slope rides 2–5 points. New in v0.5.0 (RVH-F07, commit `5a4efec`). **Fix:** restore an adequate fit-window floor (e.g. keep `n//20`, only intersect with orbital period when it is meaningfully larger). → **statistician → coder**.

### CR-09 / CR-10 — `predictive_information_gain.py` (renamed from `transfer_entropy.py`) *(Medium)*
- **CR-09 (`:212`)** `history_mode="fixed"` with `fixed_history ≥ 1` always raises at `lag=1` because `_resolve_history` enforces `history ≤ lag-1`; the whole curve aborts instead of skipping/clamping `lag=1`. Reproduced as a deterministic `ValueError`. **Fix:** skip or clamp `lag=1` under fixed history.
- **CR-10 (`:178`)** the backend literal check tests `=="rf"` but the `CMIBackendName` values are `"rf_residual"`/`"extra_trees_residual"`; `"rf_residual"` falls through the `else` and the result is labelled `"et"` while random-forest residualization actually ran. Reproduced: `.backend == "et"` for an RF run → corrupted reproducibility/audit provenance. **Fix:** compare against the actual literals. → **coder** (+ statistician sanity on CR-09's lag-1 semantics).

### CR-11 — `quality_warning` doc-vs-code drift *(Medium)*
`diagnostics/cmi_ksg.py:102` docstring (and `transfer_entropy_ksg.py:38-44`, and `tests/test_te_ksg_golden.py`'s self-contradictory docstrings) state the ratio is `N_eff / k^(d_total+2)`, but the caller passes `N_eff / k^d_total` (`:173-174`) — a ×k² (=25 for k=5) discrepancy that mislabels the user-facing reliability flag. **Fix:** reconcile code and docstrings on one definition; if `k^d_total` is intended, correct all docstrings and the golden-test commentary. → **documenter** + **statistician** to pick the canonical formula.

### CR-12 — Vectorize FP marginal counts *(Low, perf)*
`diagnostics/cmi_ksg.py:78-89` runs `[len(tree.query_ball_point(pt[i], eps[i], p=inf)) - 1 for i in range(N_eff)]` three times — `3·N_eff` scalar queries + Python `len()` under the GIL in the TE hot path. Replace each with one `tree.query_ball_point(pts, eps, p=np.inf, return_length=True, workers=-1) - 1`. → **performance_engineer**.

### CR-13 — `_compute_auc` duplication + missing empty guard *(Low)*
`domain/models/comparison_report.py:168` re-implements trapezoidal AUC already in `result_bundle._auc` (also inlined in `utils/aggregation.py` and `use_cases/extensions.py` — 4 copies). Unlike `_auc`, it has no empty-input guard, so a length-0 curve yields `AUC=0.0` and `directness_ratio=0.0` written to CSV/plot instead of `None`. **Fix:** call the canonical helper. → **coder**.

### CR-14 — Orbital-period heuristic keys off zero-fill *(Low)*
`services/lyapunov_service.py:58-63`: the strict-local-min loop falls through on a monotone-then-zero-filled AMI curve, and the `np.argmin(ami)` fallback returns the first trailing-zero index, so `orbital_period` is set by the break/zero-fill point, not the dynamics — then feeds `linear_window` (CR-08). **Fix:** ignore zero-filled tail / require a strict interior minimum before the first zero. → **statistician**.

### CR-15 — FP counts use a closed ball, contradicting their own comment *(Low)*
`diagnostics/cmi_ksg.py:72-89`: the comment says FP needs `dist < eps` strictly, but `query_ball_point(pt, eps)` counts `dist ≤ eps` and only `−1` (self) is subtracted, so the joint k-th neighbour and any exact-eps ties are over-counted. Interacts with CR-07. **Fix:** either count strictly (`searchsorted` `side` / `eps·(1−ε)` with care) or correct the comment to describe the chosen convention. → **statistician**.
