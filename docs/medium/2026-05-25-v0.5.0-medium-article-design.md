### 1. Opening (~150 words)

Hook: Good tools don't stay static. v0.5.0 is a maturity release — a deliberate
hardening pass driven by a deep audit of the toolkit's statistical foundations,
performance characteristics, and output honesty. The result is a triage workflow
that is more conservative where it should be, more transparent about its own
limitations, and now backed by a calibration run that puts real numbers behind the

### 2. What Changed for You (main body — ~900 words across 5 sub-sections)

Each sub-section: ~150–180 words. Opens with the user-facing impact statement
in **bold**, then the explanation, then (if needed) a single migration callout.

#### 2a. Your surrogate tests are now more conservative

**Impact**: The default number of surrogates used in significance tests rose from
99 to 999. If you relied on the default, your p-value resolution was coarser and
your significance threshold was less stable.

Details to include:
- 99 surrogates gives p-value resolution of 0.01; 999 gives 0.001
- The floor (minimum accepted: 99) is unchanged — explicit `n_surrogates=99` still
  works and passes validation
- Passing `n_surrogates=99` explicitly now emits no warning; values below 99 raise
  `ValidationError`
- Practitioners who set `n_surrogates` explicitly are unaffected

Migration callout (minimal code): if you pass `n_surrogates=99` you are now at the
floor — consider raising to 999 for production runs.

#### 2b. AMI curves had a small estimator bias — now corrected

**Impact**: The KSG-II mutual information estimator used an incorrect digamma
argument convention. All AMI values computed before v0.5.0 using the default
estimator carry a small systematic bias.

Details to include:
- The error: marginal count nx was computed with a +1 offset inconsistent with
  Kraskov 2004 Eq. 8's strict-inequality counting convention
- The fix aligns the implementation with the paper's closed-ball counting convention
- Effect size: small for large N; more pronounced for small N or high-d settings
- Recommendation: re-run triage on any analysis where absolute AMI values were
  interpreted quantitatively

Do NOT go into digamma mathematics — one sentence is enough.

#### 2c. Significance correction now correctly controls family-wise error rate

**Impact**: The multiple-testing correction for significance across lags now
implements true Romano-Wolf step-down FWER control. The previous implementation
used a simplified subset-max that did not strictly follow the step-down algorithm.

Details to include:
- Romano-Wolf is a resampling-based correction — conservative but honest
- The fix: step-down now operates over the remaining (not full) hypothesis set at
  each step, matching the published algorithm
- Practitioners using BH or BY correction are unaffected (those were correct)
- Effect: slightly more conservative lag selection in some edge cases

#### 2d. Low-cardinality inputs now warn instead of failing silently

**Impact**: If you passed a near-discrete series to `compute_pami_linear_residual`,
the estimator ran without complaint even when cardinality was too low for reliable
results. It now emits a `UserWarning` so you can catch it in logs.

Details to include:
- What triggers the warning: unique values / N below the cardinality threshold
- The function does not reroute to GCMI — the warning is informational, not a
  fallback trigger
- Action: inspect the warned series and decide whether to use a discrete-MI
  estimator instead

#### 2e. Output labels are now more honest about what they guarantee

**Impact**: Several docstrings and labels overclaimed. The word "deterministic"
appeared in the geometry service where the correct term is "reproducible
(seed-controlled)." The pAMI Gaussian-approximation assumption was undisclosed.
Routing threshold heuristics were presented without qualification.

Details to include:
- "Deterministic" → "reproducible (seed-controlled)" in `AmiInformationGeometryService`
- pAMI docstring now discloses the linear Gaussian approximation (I3)
- Geometry config docstring now discloses that thresholds are heuristic (I2)
- These are documentation changes — no numeric results change

### 3. Performance improvements (~200 words)

Brief, non-technical. Practitioners care that things are faster, not how.

Items to mention:
- Batched FFT phase-randomization: surrogate generation is significantly faster for
  large N
- Thin QR residualization: pAMI partial-curve path no longer allocates a full
  covariance matrix
- Request-scoped triage cache: repeated calls within the same `run_triage` invocation
  reuse intermediate results
- Welch nperseg is now adaptive to series length (fixes edge case on short series)

Close with: these changes are transparent — no API changes required.

### 4. The Calibration Section (~450–500 words) — THE EVIDENCE

This is the centrepiece. Give it room. Use a table for the numbers.

#### What we measured

After fixing the estimators, we ran a precision calibration against a synthetic
ground-truth suite: 10 archetypes × 100 independent noise replicates × N=400
observations each = 1000 triage runs. Each archetype has a known ground-truth
confidence label (HIGH / MEDIUM / LOW) derived from the data-generating process.

Archetype table — include all 10 with ground-truth label and brief rationale:

| Archetype | Ground truth | Why |
|---|---|---|
| White noise | LOW | No predictable structure |
| AR(1) φ=0.3 | MEDIUM | Weak linear structure |
| AR(1) φ=0.8 | HIGH | Strong linear structure |
| AR(2) φ=[0.6, 0.3] | HIGH | Multi-lag linear structure |
| Sine + AR(1) | HIGH | Periodic structure |
| Logistic map r=3.9 | HIGH | Deterministic chaos |
| Random walk | HIGH | Unit root, lag-1 dominance |
| Seasonal AR(1) period=12 | HIGH | Clear seasonal structure |
| MA(1) θ=0.5 | MEDIUM | Short memory |
| Heavy-noise AR(1) φ=0.1 | LOW | Near-white-noise |

#### The numbers

Results table:

| Label | Precision achieved | Target | Status | N samples |
|---|---|---|---|---|
| HIGH | **0.993** | 0.90 | PASS | 604 |
| MEDIUM | **0.584** | 0.75 | MISS | 291 |
| LOW | **0.752** | — | (no target) | 105 |

#### What the numbers mean for you

HIGH labels are reliable: when the toolkit assigns HIGH confidence, it is correct
99.3% of the time across the synthetic suite. Practitioners can treat HIGH labels
with strong confidence in analyses where N ≥ 400 and the DGP resembles one of the
standard archetypes.

MEDIUM labels require caution: the 0.584 precision means that roughly 4 in 10
MEDIUM-labelled runs are mislabelled relative to the ground truth. MEDIUM is a
useful signal — it is not noise — but it should prompt inspection rather than
automatic acceptance. This is an honest finding, not a failure: the current
thresholds are hand-picked heuristics, not calibrated against a precision target.
A full threshold sweep is planned for v0.5.1 when raw AMI peaks will be stored per
run.

#### Limitations to disclose (all 4, briefly)

1. In-sample calibration — no hold-out set; generalisation to real-world series not guaranteed
2. 10 archetypes is not exhaustive — heavy-tailed noise, structural breaks, and
   multivariate DGPs are not covered
3. Series length caveat — all archetypes used N=400; shorter series likely perform worse
4. KSG-II only — precision figures assume the v0.5.0 default estimator; KSG-I users
   should treat figures as approximate

### 5. Call to action / closing (~150 words)

**Who should re-run triage**: Anyone who interpreted absolute AMI values
quantitatively, used the default `n_surrogates=99`, or relied on MEDIUM routing
labels for automated decisions.

**Who is unaffected**: Users who set `n_surrogates` explicitly ≥ 999, used KSG-I
explicitly, or only used triage for qualitative lag screening.

**Migration**: Link to `docs/migration/v0.4.x_to_v0.5.0.md` for the complete
before/after reference.

**What's next**: v0.5.1 will introduce full threshold-sweep calibration (precision
targets met by fitting, not by hand), an expanded archetype suite (≥ 5 additional
DGPs), and a hold-out validation pass.

Close with a one-line statement of the toolkit's direction: toward triage that is
not just useful but quantifiably honest about what it guarantees.
